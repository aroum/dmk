# Руководство по интеграции Vial / VIA

Vial — это кроссплатформенное приложение с открытым исходным кодом для настройки раскладок клавиатуры, макросов и параметров в режиме реального времени. В этом руководстве объясняется, как собрать и настроить `dmk` с поддержкой Vial.

---

## 🛠️ Включение поддержки Vial

Поддержку Vial можно включить двумя способами:

1. **Через файл конфигурации клавиатуры**: Добавьте директиву `#define VIAL` в файл `config.h` вашей клавиатуры (например, в [keyboards/corne/config.h](../../keyboards/corne/config.h)). Это предпочтительный способ, так как он сохраняется непосредственно в исходном коде вашей раскладки.
2. **Через параметр сборки CMake**: Передайте флаг `-DVIAL=ON` при конфигурации сборки.

Когда поддержка Vial активна, компилируется C-модуль обработки команд и инициализируется второй USB-интерфейс **Raw HID** для обмена данными между клавиатурой и графическим интерфейсом Vial.

### Примеры команд для сборки

- **Сборка с использованием настроек в `config.h`** (если задано `#define VIAL`):
  ```bash
  ./build_all.sh -b corne --mcu rp2040 -c --uf2
  ```
- **Сборка с явной передачей флага CMake**:
  ```bash
  cmake -DVIAL=ON -DKEYBOARD=corne -DMCU=rp2040 build && cmake --build build
  ```

## 🗺️ Как это работает

1. **Определение раскладки Vial (`vial.json`)**:
   Каждая клавиатура, поддерживающая Vial, должна определить свои физические раскладки, идентификатор производителя (Vendor ID) и продукта (Product ID) в файле `vial.json` внутри каталога клавиатуры (например, `keyboards/corne/vial.json`).

2. **Автоматическое сжатие**:
   Система сборки CMake автоматически вызывает скрипт Python (`tools/vial/compress.py`) для сжатия `vial.json` с помощью алгоритма LZMA (формат контейнера `FORMAT_ALONE`). При этом в каталоге клавиатуры создается заголовочный файл C `vial_generated.h`, содержащий:
   - `vial_keyboard_def[]`: Сжатый массив определения раскладки.
   - `vial_keyboard_id[]`: Уникальный 8-байтовый идентификатор, полученный путем хеширования файла раскладки.

3. **Динамическая раскладка и энергонезависимая память (EEPROM)**:
   При запуске прошивка загружает сохраненные конфигурации из памяти EEPROM, если они есть.
   - Логика сканирования клавиш считывает данные из динамического массива.
   - Vial позволяет редактировать любые коды клавиш «на лету».
   - Изменения конфигурации (раскладка, макросы и настройки RGB) сохраняются в EEPROM (в настоящее время поддерживается на контроллерах Миландр) при отправке команды сохранения из интерфейса Vial.

## 💡 Интеграция с RGB-подсветкой

`dmk` поддерживает управление WS2812 RGB-подсветкой напрямую через интерфейс Vial:

- **Поддерживаемые контроллеры**: RP2040 (через PIO) и nRF52840 (через SPIM).
- **Возможности**: Включение/выключение подсветки, настройка яркости, выбор статического цвета (Hue и Saturation), сохранение и загрузка настроек в/из EEPROM.
- **Настройка RGB**:
- Укажите `RGB_NUM` (количество светодиодов) и `RGB_PIN` в конфигурационном файле `config.h` вашей клавиатуры (например, в [keyboards/pncateho/config.h](../../keyboards/pncateho/config.h)).
- Опционально: Определите макрос `RGB_MAP` для переопределения соответствия логических индексов светодиодов их физическому расположению.

### 🎭 Поддерживаемые RGB-эффекты

Хотя в интерфейсе Vial отображается полный список анимаций QMK, в `dmk` реализован оптимизированный набор эффектов для экономии памяти микроконтроллера. Поддерживается только первый индекс каждого типа анимации:

1. **Solid Color (Статический цвет)** (`RGBLIGHT_MODE_STATIC_LIGHT`)
2. **Breathing 1 (Дыхание 1)** (`RGBLIGHT_MODE_BREATHING`)
3. **Rainbow Mood 1 (Радужное настроение 1)** (`RGBLIGHT_MODE_RAINBOW_MOOD`)
4. **Rainbow Swirl 1 (Радужный вихрь 1)** (`RGBLIGHT_MODE_RAINBOW_SWIRL`)
5. **Snake 1 (Змейка 1)** (`RGBLIGHT_MODE_SNAKE`)
6. **Knight 1 (Рыцарь 1 / Бегущий огонь)** (`RGBLIGHT_MODE_KNIGHT`)
7. **Christmas (Рождество)** (`RGBLIGHT_MODE_CHRISTMAS`)
8. **Gradient 1 (Градиент 1)** (`RGBLIGHT_MODE_STATIC_GRADIENT`)

> [!NOTE]
> Другие вариации, отображаемые в Vial (такие как _Breathing 2–4_, _Rainbow Mood 2–3_, _Rainbow Swirl 2–6_, _Snake 2–6_, _Knight 2–3_, _Gradient 2–10_, _RGB Test_ и _Alternating_), **не реализованы** и работать не будут (эффект будет статичным или выключенным).

| **Количество слоев (Layers)**               | 🟢 Поддерживается    | Поддерживается до 16 независимых слоев.                                                                                     |
| **Тестировщик клавиш (Matrix Tester)**      | 🟢 Поддерживается    | Работает через стандартный протокол VIA/Vial без ограничений.                                                               |
| **Управление RGB (RGB Lighting)**           | 🟢 Поддерживается    | Поддерживается включение, яркость, скорость анимации и 8 стандартных QMK-эффектов/анимаций.                                 |
| **Безопасность (Unlock/Lock)**              | 🟡 Упрощено          | Блокировка раскладки обойдена (устройство всегда разблокировано для удобства настройки).                                    |
| **Макросы (Macros)**                        | 🟢 Поддерживается    | Поддерживается динамическая запись макросов (до 16 макросов, буфер 2048 байт) через графический интерфейс Vial.             |
| **Эмуляция мыши (Mousekeys)**               | 🟢 Поддерживается    | Назначение кнопок мыши, плавного 2D-перемещения курсора с физикой ускорения и колеса/панорамирования в Vial GUI (протокол v6, `0xED01`–`0xED13`). |
| **Энкодеры (Encoders)**                     | 🟢 Поддерживается    | Настройка действий при вращении по часовой (CW) и против часовой стрелки (CCW) на каждом слое через `vial_get/set_encoder` с сохранением в EEPROM. |
| **Tap Dance**                               | ❌ Не поддерживается | Динамическая настройка Tap Dance через интерфейс Vial отключена.                                                            |
| **Комбо (Combos)**                          | 🟢 Поддерживается    | Поддерживается динамическая настройка Combo (аккордов) (до 8 комбо, до 4 клавиш в каждом) через графический интерфейс Vial. |
| **Переопределение клавиш (Key Overrides)**  | ❌ Не поддерживается | Функция недоступна.                                                                                                         |

## 🖱️ Поддержка эмуляции мыши (Mousekeys)

`dmk` полностью поддерживает эмуляцию мыши USB HID с интеграцией в протокол Vial (протокол v6, коды `0xED01`–`0xED13`):

- **2D-перемещение курсора**: Непрерывное и плавное управление направлением (`KC_MS_UP`, `KC_MS_DOWN`, `KC_MS_LEFT`, `KC_MS_RIGHT`).
- **Физика плавного ускорения**: Вместо резких рывков `dmk` использует формулу динамического разгона (`MOUSEKEY_TIME_TO_MAX`, `MOUSEKEY_MAX_SPEED`, `MOUSEKEY_DECELERATION_TIME_MS`), обеспечивая точность попиксельного позиционирования при одиночном нажатии и высокую скорость перемещения при удержании.
- **Кнопки мыши**: До 5 независимых кнопок (`KC_MS_BTN1` – `KC_MS_BTN5`) для левого, правого, среднего клика, а также кнопок «Назад» и «Вперед».
- **Колесо прокрутки и панорамирование**: Вертикальный скролл (`KC_MS_WH_UP`, `KC_MS_WH_DOWN`) и горизонтальное панорамирование (`KC_MS_WH_LEFT`, `KC_MS_WH_RIGHT`).
- **Профили ускорения**: Мгновенное переключение режимов скорости с помощью клавиш `KC_MS_ACCEL0`, `KC_MS_ACCEL1` и `KC_MS_ACCEL2`.

## 🔄 Поддержка поворотных энкодеров (Rotary Encoders)

Физические энкодеры поддерживаются как полноценные элементы управления и могут настраиваться в Vial:

- **Настройка для каждого слоя**: Для каждого энкодера задаются независимые действия для вращения по часовой стрелке (CW) и против часовой стрелки (CCW) на всех слоях.
- **Интерфейс Vial GUI**: Конфигурирование в реальном времени через стандартный интерфейс энкодеров Vial (`vial_get_encoder` и `vial_set_encoder`) или команды VIA (`0x14`/`0x15`).
- **Генерация синтетических импульсов**: Каждый щелчок энкодера формирует импульс длительностью 20 мс с антидребезгом и автоматическим отжатием клавиши, что исключает «залипание» клавиш при быстром непрерывном вращении.
- **Прозрачность слоев (Transparency)**: Если действие энкодера на верхнем активном слое не назначено или задано как прозрачное (`K_TRNS` / `0x0001`), `dmk` передает обработку нижележащему активному слою.
- **Энергонезависимость**: Измененные действия энкодеров сохраняются в энергонезависимую память (EEPROM или встроенный flash) при сохранении настроек в Vial.

## 🔒 Безопасность и Тестировщик Матрицы (Matrix Tester)

- **Блокировка Vial**: Функция блокировки намеренно отключена (`VIAL_GET_UNLOCK_STATUS` всегда возвращает статус «разблокировано») для удобства настройки раскладки.
- **Особенности Matrix Tester (macOS против Windows)**:
  - **Windows**: Тестировщик матрицы работает сразу из коробки через интерфейс `hid.dll`.
  - **macOS**:
    - Приложение `vial-gui` при переходе во вкладку Matrix Tester вызывает `grabKeyboard()`, чтобы перехватывать глобальные нажатия и не давать символам вводиться в другие окна ОС. На macOS (начиная с Catalina и до Sequoia) глобальный захват клавиатуры строго требует разрешения в **Системные настройки → Конфиденциальность и безопасность → Мониторинг ввода (Input Monitoring)** или **Универсальный доступ (Accessibility)**. Без этого разрешения Qt-приложение не может захватить ввод или зависает.
    - В `dmk` внедрена очередь ответов Raw HID, благодаря чему интенсивный опрос матричного тестера (50–100 Гц) не теряет пакеты, даже если конечная точка USB IN временно занята.
    - В качестве альтернативы на macOS можно использовать веб-клиент [Vial WebHID Client](https://vial.rocks/) в браузере Chrome или Edge, которому не требуются системные разрешения на перехват клавиатуры.

## 🧪 Тестирование

1. Подключите клавиатуру к компьютеру.
2. Перейдите на страницу [Vial Web Client](https://vial.rocks/) или скачайте настольное приложение.
3. Нажмите кнопку "Start Vial" и выберите обнаруженную клавиатуру.
4. Измените любую клавишу или настройте подсветку в интерфейсе приложения и убедитесь, что изменения немедленно применились к вашей клавиатуре!
