# Руководство по раскладке и поведению клавиш

## Логические раскладки и слои

Чтобы избежать дублирования выделения переменных в нескольких единицах компиляции, раскладки, макросы и размеры слоев определяются внутри блока `#ifdef DEFINE_KEYMAP` в `config.h`. Ядро прошивки определяет `DEFINE_KEYMAP` перед включением `config.h` внутри `brain.c` для инициализации переменных.

### Встраивание раскладки

Раскладки определяются как трехмерный массив: `const uint32_t keymap[][NUM_ROWS][NUM_COLS]`.

```c
#ifdef DEFINE_KEYMAP
#define DEF 0
#define FN1 1

const uint32_t keymap[][NUM_ROWS][NUM_COLS] = {
    [DEF] = {
       { K_Q,    K_W,    K_E,    K_R,    K_T,         K_Y,    K_U,    K_I,    K_O,   K_P },
       { K_A,    K_S,    K_D,    K_F,    K_G,         K_H,    K_J,    K_K,    K_L,   K_ENT },
       { K_Z,    K_X,    K_C,    K_V,    K_B,         K_N,    K_M,    K_ALT,  K_CTRL,K_SHFT },
       { K_NO,   K_NO,   K_NO,   K_BSPC, FN1,         K_SPC,  K_TRNS, K_NO,  K_NO,  K_NO }
    },
    [FN1] = {
       { K_ESC,  K_APOS, K_A_U,  K_BRAL, K_BRAR,      K_7,    K_8,    K_9,    K_MIN, K_SLSH },
       { K_TAB,  K_A_L,  K_A_D,  K_A_R,  K_HASH,      K_4,    K_5,    K_6,    K_EQU, K_ENT },
       { K_SHFT, K_BKSL, K_SCLN, K_COMM, K_DOT,       K_1,    K_2,    K_3,    K_ALT, K_SHFT },
       { K_NO,   K_NO,   K_NO,   K_BSPC, K_TRNS,      K_0,    K_TRNS, K_NO,  K_NO,  K_NO }
    }
};

const size_t keymap_layers = sizeof(keymap) / sizeof(keymap[0]);
#endif
```

> [!NOTE]
> Для простого переключения слоев без модификаторов вы можете использовать коды клавиш `L_0` - `L_15` напрямую (например, `L_1` временно переключает на слой 1). Это более легкая альтернатива макросу `MO(layer)`, которая обрабатывается мгновенно в цикле сканирования.
>
> Полный список кодов клавиш смотрите в файле [keycodes.md](keycodes.md).

### Опциональная внешняя раскладка

Если вы хотите хранить раскладку в отдельном файле, система поддерживает подключение `keymap_external.h`, если он присутствует в папке клавиатуры:

```c
#ifdef DEFINE_KEYMAP
#if __has_include("keymap_external.h")
    #include "keymap_external.h"
#else
    // Встроенное определение раскладки...
#endif
#endif
```

## Макросы (Macros)

В прошивке реализован движок выполнения макросов, позволяющий симулировать последовательность нажатий и отпусканий клавиш с задержками (в миллисекундах).

### Определение действий макроса

Каждая макро-команда (шаг макроса) описывается структурой `MacroStep` и состоит из типа действия (`MacroAction`) и связанного значения (код клавиши или время задержки в мс):

- **`KEY_DOWN`** (или вспомогательный макрос `M_DN(key)`) — нажатие и удержание клавиши.
- **`KEY_UP`** (или вспомогательный макрос `M_UP(key)`) — отпускание клавиши.
- **`DELAY`** (или вспомогательный макрос `M_D(ms)`) — задержка выполнения следующего шага в миллисекундах.

#### Пример объявления шагов макроса

```c
#include "keys.h"

// Макрос для эмуляции последовательности Alt + Tab
const MacroStep MACRO_ALT_TAB[] = {
    M_DN(K_ALT),   // Зажать Alt
    M_D(200),      // Подождать 200 мс
    M_DN(K_TAB),   // Зажать Tab
    M_D(200),      // Подождать 200 мс
    M_UP(K_TAB),   // Отпустить Tab
    M_UP(K_ALT)    // Отпустить Alt
};
```

### Регистрация макросов в config.h

Чтобы прошивка распознала ваши макросы, они должны быть зарегистрированы в глобальном массиве `keyboard_macros` в файле [config.h](config.md) вашей клавиатуры.

```c
// 1. Объявление массивов шагов макроса
const MacroStep MACRO_ALT_TAB[] = {
    M_DN(K_ALT), M_D(200), M_DN(K_TAB), M_D(200), M_UP(K_TAB), M_UP(K_ALT)
};

const MacroStep MACRO_HELLO[] = {
    M_DN(K_H), M_UP(K_H),
    M_DN(K_E), M_UP(K_E),
    M_DN(K_L), M_UP(K_L),
    M_DN(K_L), M_UP(K_L),
    M_DN(K_O), M_UP(K_O)
};

// 2. Регистрация их в массиве keyboard_macros
const Macro keyboard_macros[] = {
    [0] = { MACRO_ALT_TAB, sizeof(MACRO_ALT_TAB) / sizeof(MACRO_ALT_TAB[0]) },
    [1] = { MACRO_HELLO, sizeof(MACRO_HELLO) / sizeof(MACRO_HELLO[0]) }
};

// 3. Определение общего количества макросов
const uint8_t keyboard_macros_count = sizeof(keyboard_macros) / sizeof(keyboard_macros[0]);
```

### Использование макросов в раскладке (Keymap)

Для привязки макроса к определенной клавише используется макрос `M(index)`, где `index` — порядковый номер макроса в массиве `keyboard_macros` (начиная с `0`):

```c
const uint32_t keymap[][NUM_ROWS][NUM_COLS] = {
    [0] = {
        { K_Q, K_W, K_E, K_R, K_T, K_Y, K_U, K_I, K_O, M(0) }, // M(0) запускает Alt+Tab
        { K_A, K_S, K_D, K_F, K_G, K_H, K_J, K_K, K_L, M(1) }, // M(1) вводит "hello"
        ...
    }
};
```

> [!TIP]
> **Переключение языковых раскладок через макрос и слои:**
> С помощью макроса можно организовать изолированную раскладку для другого языка в ОС. Для этого создается макрос, который отправляет сочетание клавиш смены языка в операционной системе (например, `Shift + Alt` или `Win + Space`) и одновременно переключает слой прошивки (например, через `TG(1)` или `MO(1)`):
>
> ```c
> // Макрос: Переключить язык в ОС (Shift + Alt) и включить слой с русской раскладкой
> const MacroStep MACRO_SWITCH_LANG_RU[] = {
>     M_DN(K_LSFT),
>     M_DN(K_LALT),
>     M_UP(K_LALT),
>     M_UP(K_LSFT),
>     M_DN(TG(1)), // Переключение на слой 1 (русские символы)
>     M_UP(TG(1))
> };
> ```
>
> Это позволяет иметь на отдельном слое символы, специфичные для другой языковой раскладки ОС, сохраняя синхронизацию языка при переключении.

## Аккорды (Chords)

```c
// Упаковываем три координаты в один байт (8 бит)
typedef struct {
    uint8_t row   : 2; // 2 бита для строк (0..3)
    uint8_t col   : 4; // 4 бита для колонок (0..15)
    uint8_t layer : 2; // 2 бита для слоев (0..3)
} PackedKey;
```

```c
#include <stdint.h>
#include <stdbool.h>

// Структура для одной физической кнопки на определенном слое
typedef struct {
    uint8_t row;
    uint8_t col;
    uint8_t layer;
} KeyCoord;

// Максимальное количество одновременно зажатых клавиш в одном аккорде
#define MAX_CHORD_KEYS 4 

// Структура аккорда
typedef struct {
    KeyCoord keys[MAX_CHORD_KEYS]; // Массив кнопок, составляющих аккорд
    uint8_t key_count;             // Сколько реально кнопок в этом аккорде
    void (*action)(void);          // Указатель на функцию, которая выполнится при срабатывании
} Chord;

// Макрос для создания одной кнопки: К(Row, Col, Layer)
#define K(r, c, l) {r, c, l}

// Функции-действия, которые будут вызываться при активации аккордов
void do_copy(void) { /* Код для Ctrl+C */ }
void do_paste(void) { /* Код для Ctrl+V */ }

// Список всех аккордов в прошивке
const Chord my_chords[] = {
    // Аккорд 1: Зажаты кнопки (0,1) и (0,2) на 0-м слое -> Срабатывает функция do_copy
    {  
        .keys = { K(0,1,0), K(0,2,0) }, 
        .key_count = 2, 
        .action = do_copy 
    },
    
    // Аккорд 2: Три кнопки на 1-м слое
    {  
        .keys = { K(1,1,1), K(1,2,1), K(2,0,1) }, 
        .key_count = 3, 
        .action = do_paste 
    },
};

#define CHORDS_COUNT (sizeof(my_chords) / sizeof(my_chords[0]))
```

## Модификаторы и Слои (Mod/Layer)

Поддерживается до 16 слоев.

### Временная активация слоя/модификатора (Momentary)

- FN1/LSHIFT > Временно активирует слой/модификатор. Как только вы отпускаете клавишу, слой деактивируется.

- `L_0` ... `L_15` > Прямой временный переключатель слоев. Мгновенно переключает бит конкретного слоя (например, `L_1` для слоя 1) во время удержания. Это более легкая альтернатива `MO(layer)` и напрямую сопоставляется с индексами слоев.

```c
// --------------------------------------------------------------------------
// ЧИСТЫЕ СЛОИ И ДРУГИЕ РЕЖИМЫ
// --------------------------------------------------------------------------

// Идентификаторы слоев
enum layers {
    BASE_LAYER = 0, 
    FN1,            
    NUM_LAYER       
};

// ==========================================================================
// 3. РАСКЛАДКА С ОБНОВЛЕННЫМ MO (keymap.c)
// ==========================================================================

const uint16_t keymaps[][MATRIX_ROWS][MATRIX_COLS] = {
    
    // СЛОЙ 0: Основная раскладка
    [BASE_LAYER] = LAYOUT(
        // FN1 -> Теперь это просто имя слоя. Прошивка видит его и понимает: 
        //        "Активировать слой 1, пока кнопка зажата" (чистый Momentary).
        FN1, 
    )
};
```

### Модифицированная клавиша (Modified key)

```c
// --------------------------------------------------------------------------
// МАКРОСЫ ДЛЯ MODIFIED KEYS (MK)
// Позволяют упаковать модификаторы и клавишу в один бинд.
// --------------------------------------------------------------------------

// Упаковка: Верхний байт — маска модификаторов, Нижний байт — код клавиши
#define MK(mod_mask, kc) (DMK_MK | ((mod_mask) << 8) | (kc))

// Ваши кастомные бинды:
// MK_S_A     -> Нажатие выдаст Shift + A
// MK_SA_A    -> Нажатие выдаст Shift + Alt + A
#define MK_S_A    MK(MOD_LSHIFT, K_A)
#define MK_SA_A   MK(MOD_LSHIFT | MOD_LALT, K_A)
```

### Залипающие клавиши (ONE SHOT)

Подробнее о концепции можно прочитать в документации [ZMK Sticky Key](https://zmk.dev/docs/keymaps/behaviors/sticky-key).

- OS > Временно активирует слой или модификатор до нажатия следующей клавиши.

```c
// ==========================================================================
// 1. ПАРАМЕТРЫ КОНФИГУРАЦИИ (Обычно находятся в config.h)
// ==========================================================================
// Время ожидания (в мс). Если за 1.5 секунды после тапа OS-клавиши 
// не нажата следующая кнопка, модификатор автоматически отжимается.
#define ONESHOT_TIMEOUT 1500

// 1 - Включен: Модификатор отключается сразу в момент НАЖАТИЯ (press) следующей клавиши.
//             Это предотвращает случайное залипание на вторую букву при быстром вводе.
// 0 - Выключен: Модификатор активен до тех пор, пока следующая клавиша не будет ОТПУЩЕНА (release).
#define ONESHOT_QUICK_RELEASE 1

// [lazy]
// 1 - Включен: Клавиатура НЕ отправляет модификатор в компьютер сразу при тапе.
//             Он отправится в ОС только ПЕРЕД нажатием следующей обычной клавиши.
//             Защищает от вызова меню "Пуск" в Windows при случайном тапе по OS_GUI.
// 0 - Выключен: Модификатор отправляется в хост сразу в момент тапа по OS-клавише.
#define ONESHOT_LAZY 1

// Примечание: Комбинирование (Callum-style) активно по умолчанию на уровне прошивки.
//              Если нажать один OS-мод, пока активен другой, они объединятся (например, OS_SHIFT + OS_CTRL).
#define ONESHOT_COMBINE_MODIFIERS 1

// Дополнительный режим: двойной тап по OS-клавише «намертво» блокирует её 
// во включенном состоянии (до третьего нажатия). [Пока не реализовано]
#define ONESHOT_TAP_TOGGLE 0

// Примечание: Активно по умолчанию на уровне прошивки. Если держать клавишу
//              дольше TAPPING_TERM, она временно превращается в обычный удерживаемый модификатор/слой.
#define ONESHOT_HOLD_TRIGGER 1
// ==========================================================================
// 2. БИНДЫ И МАКРОСЫ ДЛЯ РАСКЛАДКИ (Инструментарий)
// ==========================================================================

// Системные маски базовых модификаторов
#define MOD_LCTRL  (1 << 0)
#define MOD_LSHIFT (1 << 1)
#define MOD_LALT   (1 << 2)
#define MOD_LGUI   (1 << 3)

// Маска для Hyper Key (эквивалент комбинации &sk LG(LS(LA(LCTRL))))
#define MOD_HYPER (MOD_LCTRL | MOD_LSHIFT | MOD_LALT | MOD_LGUI)

// Универсальный макрос One-Shot (OS).
// Если аргумент < 32, он работает как One-Shot слоя.
// Если аргумент >= 32, он работает как One-Shot модификатора.
#define OS(val) (DMK_OS | (val))

// Быстрые сокращения для OSM (One Shot Modifiers)
#define OS_SHIFT   OS(MOD_LSHIFT)
#define OS_CTRL    OS(MOD_LCTRL)
#define OS_ALT     OS(MOD_LALT)
#define OS_GUI     OS(MOD_LGUI)
#define OS_HYPER   OS(MOD_HYPER) // Тот самый &sk LG(LS(LA(LCTRL)))


// ==========================================================================
// 3. ПРИМЕР ИСПОЛЬЗОВАНИЯ В РАСКЛАДКЕ (keymap.c)
// ==========================================================================


// Двухслойная матрица клавиатуры
const uint32_t keymap[][NUM_ROWS][NUM_COLS] = {
    
    // СЛОЙ 0: Основная раскладка
    [BASE_LAYER] = {
        { K_Q,     K_W,     K_E,    K_R,    K_T,
        
        // OS(NUM_LAYER)   -> Тапнули и отпустили: следующая клавиша будет цифрой, 
        //                        после чего клавиатура сама вернется на BASE_LAYER.
        // OS_HYPER            -> Тапнули и отпустили: активирует Ctrl+Shift+Alt+Cmd 
        //                        для следующей нажатой клавиши (запуск шорткатов ОС).
        OS(NUM_LAYER), OS_HYPER, K_S, K_D, K_SPC }
    },

    // СЛОЙ 1: Цифры
    [NUM_LAYER] = {
        { K_1,    K_2,    K_3,    K_TRNS, K_TRNS,
        
        // OS_SHIFT            -> Тапнули и отпустили: временно включает Shift.
        //                        Удобно, если на цифровом слое нужно разово ввести символ.
        OS_SHIFT, K_TRNS, K_TRNS, K_TRNS, K_TRNS }
    }
};
```

### Удержание-Тап (Hold-Tap)

- HT > Слой-тап/Модификатор-тап. Временно активирует слой или модификатор при удержании, и отправляет код обычной клавиши при быстром тапе. Поддерживает слои 0-15.

В синтаксисе прошивок на **C** разделение между `Mod-Tap` (`&mt`) и `Layer-Tap` (`&lt`) часто стирается, так как обе сущности упаковываются в одну универсальную функцию **Hold-Tap (HT)**. Прошивка сама понимает, что ей делать: если переданный индекс меньше 16 — активируется слой, если передана маска модификатора — активируется модификатор.

```c
// Время (в мс), в течение которого нужно удерживать клавишу, чтобы она 
// распозналась как "Hold" (активация слоя или модификатора).
#define TAPPING_TERM_DEFAULT 200

// Аналоги "Flavors" (Режимы приоритета для Hold-Tap):
// В ZMK есть режимы hold-preferred, tap-preferred, balanced. В C они задаются так:

// 1 - hold-preferred: Модификатор/слой активируется мгновенно при зажатии.
// 0 - tap-preferred: Если клавиша нажата и отпущена в пределах TAPPING_TERM, 
//     она СТРОГО отправит код клавиши (kc), даже если была задета соседняя кнопка.
#define HOLD_TAP_TAP_PREFERRED 1 

// Разрешить сквозной повтор (Permissive Hold):
// Если включено (1), то нажатие и отпускание ДРУГОЙ клавиши во время удержания 
// нашей HT-клавиши сразу активирует режим "Hold", не дожидаясь истечения 200мс.
#define PERMISSIVE_HOLD 1

// [Универсальный Hold-Tap макрос]
// Заменяет собой и &mt, и &lt из ZMK.
// Аргумент layer_or_mod: если передаем 0-15 — это слой (Layer-Tap),
//                        если передаем маску (напр. MOD_LSHIFT) — это модификатор (Mod-Tap).
#define HT(layer_or_mod, kc)    (DMK_HT | ((layer_or_mod) << 8) | (kc))

// Аналог создания кастомного hold-tap узла с индивидуальным таймаутом
#define HT_T(layer_or_mod, kc, ms) (DMK_HT | ((layer_or_mod) << 8) | (kc) | ((uint32_t)(ms) << 16))


// ==========================================================================
// 3. РАСКЛАДКА С ПРИМЕРАМИ ИСПОЛЬЗОВАНИЯ (keymap.c)
// ==========================================================================

enum layers {
    BASE_LAYER = 0, 
    FN1             // Слой 1 (попадает в диапазон 0-15)
};


const uint32_t keymap[][NUM_ROWS][NUM_COLS] = {
    
    [BASE_LAYER] = {
        // 1. АНАЛОГ LAYER-TAP (&lt 1 A)
        // Зажимаем: активируется слой 1 (FN1). Тапаем: отправляет обычную букву 'A'.
        { HT(FN1, K_A),

        // 2. АНАЛОГ MOD-TAP (&mt LSHIFT F)
        // Зажимаем: работает как левый Shift. Тапаем: отправляет букву 'F'.
        // Прошивка сама видит маску MOD_LSHIFT и обрабатывает это как Mod-Tap, а не Layer-Tap.
        HT(MOD_LSHIFT, K_F),

        // 3. АНАЛОГ КАСТОМНОГО HOLD-TAP С ИНДИВИДУАЛЬНЫМ ТАЙМИНГОМ
        // Для этой конкретной клавиши (Пробел / Ctrl) тайминг удержания увеличен до 300мс.
        HT_T(MOD_LCTRL, K_SPC, 300) }
    }
};
```

### Переключение слоя (Toggle)

- TG > Переключатель слоя. Активирует слой, если он неактивен, и наоборот.

```c
#define TG(layer)    (DMK_TG | (layer))

// ==========================================================================
// 3. РАСКЛАДКА С ПРИМЕРАМИ ИСПОЛЬЗОВАНИЯ (keymap.c)
// ==========================================================================

enum layers {
    BASE_LAYER = 0, 
    FN1             // Слой 1 (попадает в диапазон 0-15)
};


const uint32_t keymap[][NUM_ROWS][NUM_COLS] = {
    
    [BASE_LAYER] = {
        { TG(FN1) }
    }
};
```

### Мультимедийные клавиши (Consumer Media Keys)

Чтобы использовать мультимедийные клавиши Consumer Page в вашей раскладке (например, `K_MUTE`, `K_VOLU`, `K_VOLD`, `K_PLAY` и т. д.), вы должны включить макрос `EXTRAKEY_ENABLE` в файле config.h вашей клавиатуры. Подробности см. в [config.md](config.md) и [keycodes.md](keycodes.md).

## Настройка энкодеров

Если ваша клавиатура оснащена вращающимися энкодерами, вы можете настроить их пины, разрешение и действия для каждого направления вращения. Энкодеры поддерживают слои клавиатуры: при переключении слоя клавиатуры автоматически переключаются и действия энкодеров.

Если пины энкодеров не заданы в `config.h`, код поддержки энкодеров автоматически исключается из сборки.

### Назначение пинов

Для настройки энкодеров укажите массивы пинов `A` и `B` в файле `config.h`. Количество пинов в обоих массивах должно совпадать:

```c
#define ENCODER_PINS_A  { GPIO9, GPIO10 }
#define ENCODER_PINS_B  { GPIO11, GPIO12 }
```

### Разрешение (Resolution)

Разрешение определяет количество изменений состояния квадратурного сигнала (шагов), необходимых для отправки одного нажатия клавиши. По умолчанию разрешение равно `4`. Вы можете изменить его следующим образом:

```c
// Задать фиксированное разрешение для всех энкодеров:
#define ENCODER_RESOLUTION 2

// Или индивидуально для каждого энкодера:
#define ENCODER_RESOLUTIONS { 2, 4 }

// Альтернативно, можно указать количество шагов фиксации (detents) и импульсов (pulses),
// чтобы разрешение рассчиталось автоматически (detents / pulses):
#define ENCODER_DETENTS { 30, 24 }
#define ENCODER_PULSES  { 15, 24 }
```

### Раскладка энкодеров (Encoder Keymap)

Карта клавиш для энкодеров определяется как трехмерный массив внутри блока `DEFINE_KEYMAP` в `config.h`. Массив должен иметь такое же количество слоев, как и основная клавиатурная раскладка `keymap`:

```c
#ifdef DEFINE_KEYMAP
#define DEF 0
#define FN1 1

const uint32_t encoder_keymap[][NUM_ENCODERS][2] = {
    [DEF] = {
        { K_VOLU, K_VOLD }, // Энкодер 1: по часовой (CW), против часовой (CCW)
        { K_LEFT, K_RIGHT } // Энкодер 2: CW, CCW
    },
    [FN1] = {
        { K_MNXT, K_MPRV }, // Энкодер 1 на слое FN1
        { K_TRNS, K_TRNS }  // Энкодер 2 (прозрачный переход)
    }
};
#endif
```
