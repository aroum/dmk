### Архитектура интерфейса PIO в Baikal BE-U1000
Микроконтроллер Baikal BE-U1000 содержит независимое третье 32-разрядное ядро RISC-V: **CloudBEAR BM-310 (Core 2)**, работающее на частоте до 100 МГц и обладающее 10 КБ собственной быстрой памяти TCM (`TCMA` 2 КБ + `TCMB` 8 КБ).

* **Назначение**: Программная реализация внешних цифровых интерфейсов и протоколов (Programmable Input/Output, PIO).
* **Аппаратный регистр**: Ядро Core 2 управляет выделенным 16-битным регистром быстрого параллельного доступа `CORE2_PIO` (`IN`, `EN`, `OU`) за 1 такт.
* **Топология выводов кристалла**: 16 линий `PIO[0]`..`PIO[15]` аппаратно выведены через матрицу мультиплексирования чипа **исключительно на выводы порта PC** (`PC[0]`–`PC[15]` в режиме альтернативной функции `АФ 1`).
* **Ограничение портов PA и PB**: Выводы портов **PA** и **PB** физически не имеют доступа к шине PIO ядра Core 2. Любые протоколы на базе сопроцессора Core 2 PIO должны подключаться к ножкам порта PC.

## Назначение пинов для RGB-подсветки

В зависимости от аппаратной платформы микроконтроллера, выбор пинов для подключения линии данных WS2812 RGB-подсветки ограничен используемыми аппаратными интерфейсами:

- **Milandr (K1986BE92FI)**: Подсветка работает через аппаратные блоки SSP (SPI). Вы **должны** подключить сигнальный провод RGB-подсветки к одному из следующих аппаратных TXD-пинов:
  - **SSP1**: `PA15` или `PF0`
  - **SSP2**: `PD3` или `PD15`
- **Raspberry Pi (RP2040/RP2350)**: Подсветка работает через аппаратные программируемые автоматы ввода-вывода (PIO). Можно назначить **любой** свободный GPIO-пин (`GPIO0`-`GPIO29` / `GPIO0`-`GPIO47`).
- **nRF52840**: Подсветка работает через аппаратный модуль SPIM1 (SPI master). Поддерживается перенаправление на **любой** GPIO-пин (`P0_00`-`P0_31` / `P1_00`-`P1_15`).
- **Baikal (be-u1000)**: Подсветка работает через калиброванный по тактам программный GPIO-драйвер в критической секции FreeRTOS (`taskENTER_CRITICAL()`) на основном ядре CloudBEAR BR-350 с частотой 200 МГц (шаг дискретизации 5 нс). Это позволяет подключать ленты WS2812 к **любому** GPIO-пину (`PA0`-`PA15`, `PB0`-`PB15`, `PC0`-`PC15`), включая `PA6` / `PM_1` на Kabarga CE, без привязки к шине SPI или аппаратному PIO.

## Назначение пинов для связи половинок (UART)

Обе половины должны использовать одинаковый формат split-пакетов. Текущий формат содержит номер и CRC и несовместим со старой прошивкой; обновляйте обе половины одновременно.

Слейв передаёт координаты матрицы, а мастер разрешает слои и коды клавиш. После каждого пакета матрицы слейв открывает окно ответа, в котором мастер передаёт маску обычных светодиодов или цвет одного RGB-светодиода. Значения повторяются для восстановления после потери ответа. Обычные светодиоды соответствуют первым восьми элементам `LED_PINS`. По умолчанию на слейв зеркалируются логические RGB-пиксели мастера с индекса 0; `SPLIT_RGB_OFFSET` задаёт первый индекс на мастере, а `SPLIT_REMOTE_RGB_COUNT` — число пикселей слейва (по умолчанию `RGB_NUM`, максимум 255). Модуль также может вызывать `split_set_remote_leds(mask)` и `split_set_remote_rgb(index, color)`. Обе половины необходимо обновить одновременно. Тайминги и переподключение требуется проверить на реальном устройстве.

Для раздельных клавиатур сигнальный провод связи (`SERIAL_PIN`) работает как однопроводной полудуплексный интерфейс. На поддерживаемых платформах доступно два режима:

1. **Bit-Bang (по умолчанию)**: Программная эмуляция UART.
   - **Особенности**:
     - Использует **ровно 1 любой свободный GPIO-пин**.
     - Передача помещается в очередь отдельной задачи. Для тайминга каждого UART-байта используется короткая критическая секция; обмен включает импульс пробуждения и окно ответа.
     - Не требует подтягивающих резисторов (использует встроенную подтяжку).
   - **Поддерживаемые платформы**: Milandr, Raspberry Pi, nRF52840, Baikal.

2. **Аппаратный / PIO полудуплексный режим**:
   В зависимости от архитектуры микроконтроллера, для аппаратной связи может требоваться либо один пин, либо физическое объединение двух пинов (TX и RX) на плате:

   - **Решения на одном пине**:
     - **nRF52840**: **Поддерживает работу на одном пине**. Благодаря гибкой матрице коммутации (GPIO crossbar), сигналы TXD и RXD аппаратного периферийного модуля UARTE можно назначить на **один и тот же физический GPIO-пин** (например, `P0_06`). При этом пин настраивается в режим открытого стока с подтяжкой (встроенной или внешней).
     - **Raspberry Pi (RP2040/RP2350)**: **Поддерживают работу на одном пине**. Используются программируемые автоматы ввода-вывода (PIO) для программно-аппаратного переключения направления одного пина «на лету».
     - **Baikal (be-u1000)**: Однопроводная связь половинок поддерживается через программный **Software Bit-Bang (`SOFT`)** на любом свободном GPIO-пине. Для аппаратного UART (`HW_FULL_DUPLEX`) задействуются два физических пина (`SPLIT_TX_PIN` и `SPLIT_RX_PIN`), так как встроенные контроллеры UART чипа не имеют встроенного режима полудуплекса по одному проводу.
     - **STM32**: **Поддерживает работу на одном пине**. Встроенный USART имеет режим Single-wire (бит `USART_CR3_HDSEL` в QMK/ChibiOS), который внутри чипа перекоммутирует приёмник на линию TX. Используется только пин TX.

   - **Решения с объединением пинов**:
     - **Milandr (K1986BE92FI)**: **Требует физического соединения двух пинов**. Встроенный контроллер UART (ARM PL011) не имеет режима Single-wire, а структура мультиплексора GPIO не позволяет назначить функции TX и RX на один и тот же пин. Для использования аппаратного UART необходимо **физически соединить пины TX и RX вместе на плате** и подключить к линии связи. Пин TX настраивается как открытый сток (open-drain) с подтяжкой.
     - **Доступные аппаратные пары пинов на Milandr**:
       - **UART1**: TX `PC3` + RX `PC4` (основные) или TX `PB5` + RX `PB6` (альтернативные)
       - **UART2**: TX `PF1` + RX `PF0` (оверрайд) или TX `PD1` + RX `PD0` (альтернативные)

   - **Настройка**: Включается через дефайн `#define SPLIT_UART_HARDWARE` в `config.h` клавиатуры.
   - **Подтягивающий резистор**: Для всех аппаратных конфигураций с открытым стоком (open-drain) обязателен подтягивающий резистор (встроенный `SPLIT_UART_PULLUP 1` или внешний номиналом 1.5кОм–8.2кОм к линии VCC) для корректной установки высокого уровня на шине в состоянии покоя. (Исключение: RP2040 с PIO, где внешняя подтяжка не требуется).

### Распиновка ProMicro

Псевдонимы пинов ProMicro (`PM_0`..`PM_21`) позволяют создавать конфигурации клавиатур, аппаратно совместимые с распиновкой ProMicro на всех поддерживаемых платформах микроконтроллеров. Они автоматически доступны при подключении `"pin_defs.h"`:

```c
#include "pin_defs.h"
```
