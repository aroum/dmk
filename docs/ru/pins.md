## Назначение пинов для RGB-подсветки

В зависимости от аппаратной платформы микроконтроллера, выбор пинов для подключения линии данных WS2812 RGB-подсветки ограничен используемыми аппаратными интерфейсами:

- **Milandr (K1986BE92FI)**: Подсветка работает через аппаратные блоки SSP (SPI). Вы **должны** подключить сигнальный провод RGB-подсветки к одному из следующих аппаратных TXD-пинов:
  - **SSP1**: `PA15` или `PF0`
  - **SSP2**: `PD3` или `PD15`
- **Raspberry Pi (RP2040/RP2350)**: Подсветка работает через программируемые автоматы ввода-вывода (PIO). Можно назначить **любой** свободный GPIO-пин (`GPIO0`-`GPIO29` / `GPIO0`-`GPIO47`).
- **nRF52840**: Подсветка работает через аппаратный модуль SPIM1 (SPI master). Поддерживается перенаправление на **любой** GPIO-пин (`P0_00`-`P0_31` / `P1_00`-`P1_15`).
- **Baikal (be-u1000)**: Подсветка работает через программируемые автоматы ввода-вывода (PIO). Можно назначить **любой** свободный GPIO-пин (`PA0`-`PA15`, `PB0`-`PB15`, `PC0`-`PC15`).

## Назначение пинов для связи половинок (UART)

Для раздельных клавиатур сигнальный провод связи (`SERIAL_PIN`) работает как однопроводной полудуплексный интерфейс. На поддерживаемых платформах доступно два режима:

1. **Bit-Bang (по умолчанию)**: Программная эмуляция UART.
   - **Особенности**:
     - Использует **ровно 1 любой свободный GPIO-пин**.
     - На Milandr и nRF52840 этот режим выполняется синхронно в критической секции процессора, что повышает пиковую нагрузку при обработке пакетов.
     - Не требует подтягивающих резисторов (использует встроенную подтяжку).
   - **Поддерживаемые платформы**: Milandr, Raspberry Pi, nRF52840, Baikal.

2. **Аппаратный / PIO полудуплексный режим (Hardware / PIO)**:
   В зависимости от архитектуры микроконтроллера, для аппаратной связи может требоваться либо один пин, либо физическое объединение двух пинов (TX и RX) на плате:

   - **Решения на одном пине (Single-Pin)**:
     - **nRF52840**: **Поддерживает работу на одном пине**. Благодаря гибкой матрице коммутации (GPIO crossbar), сигналы TXD и RXD аппаратного периферийного модуля UARTE можно назначить на **один и тот же физический GPIO-пин** (например, `P0_06`). При этом пин настраивается в режим открытого стока с подтяжкой (встроенной или внешней).
     - **Raspberry Pi (RP2040/RP2350) и Baikal (через PIO)**: **Поддерживают работу на одном пине**. Используются программируемые автоматы ввода-вывода (PIO) для программно-аппаратного переключения направления одного пина «на лету».
     - **STM32**: **Поддерживает работу на одном пине**. Встроенный USART имеет режим Single-wire (бит `USART_CR3_HDSEL` в QMK/ChibiOS), который внутри чипа перекоммутирует приёмник на линию TX. Используется только пин TX.

   - **Решения с объединением пинов (Tied TX/RX)**:
     - **Milandr (K1986BE92FI)**: **Требует физического соединения двух пинов**. Встроенный контроллер UART (ARM PL011) не имеет режима Single-wire, а структура мультиплексора GPIO не позволяет назначить функции TX и RX на один и тот же пин. Для использования аппаратного UART необходимо **физически соединить пины TX и RX вместе на плате** и подключить к линии связи. Пин TX настраивается как открытый сток (open-drain) с подтяжкой.
     - **Доступные аппаратные пары пинов на Milandr**:
       - **UART1**: TX `PC3` + RX `PC4` (основные) или TX `PB5` + RX `PB6` (альтернативные)
       - **UART2**: TX `PF1` + RX `PF0` (оверрайд) или TX `PD1` + RX `PD0` (альтернативные)

   - **Настройка**: Включается через дефайн `#define SPLIT_UART_HARDWARE` в `config.h` клавиатуры.
   - **Подтягивающий резистор (Pull-up)**: Для всех аппаратных конфигураций с открытым стоком (open-drain) обязателен подтягивающий резистор (встроенный `SPLIT_UART_PULLUP 1` или внешний номиналом 1.5кОм–8.2кОм к линии VCC) для корректной установки высокого уровня на шине в состоянии покоя. (Исключение: RP2040 с PIO, где внешняя подтяжка не требуется).
