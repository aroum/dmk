# Бэкап и восстановление

Перед обновлением сохраните Flash, EEPROM и Option Bytes. EEPROM содержит индивидуальные заводские пороги и настройки; не переносите EEPROM между клавиатурами.

## Системный ROM DFU STM32

Системный ROM DFU STM32 — отдельный режим, не зависящий от DMK, Bank 1 или установленного образа Bank 2. Он работает без отладчика.

1. Разберите клавиатуру и снимите металлический экран с обратной стороны контроллера, чтобы получить доступ к плате.
2. При подключении USB замкните пинцетом или перемычкой **правые площадки резисторов R6 и R85**. Это поднимает BOOT0 и запускает системный загрузчик STM32. Ориентацию «правые» определяйте по фотографии, а не по произвольному положению платы; перед замыканием сверьте маркировку и площадки.
3. В исходном наблюдении индикатор загорается оранжевым. Проверьте режим по USB: STM32 DFU обычно определяется как `0483:df11`, затем уберите перемычку.

![Площадки R6 и R85 для входа в ROM DFU](https://i.imgur.com/oTwQLPg.jpeg)

Проверка устройства:

```bash
dfu-util -l
```

### Бэкап через DFU

```bash
dfu-util -a 0 -s 0x08000000:131072 -U hhkb-flash-full.bin
dfu-util -a 2 -s 0x08080000:6144 -U hhkb-eeprom.bin
dfu-util -a 1 -s 0x1FF80000:32 -U hhkb-option-bytes.bin
```

Полный дамп Flash содержит Bank 1 и Bank 2, но не EEPROM и не Option Bytes.

### Восстановление через DFU

DFU записывает сырой `.bin`, а не `.hfb`. Чтобы восстановить только Bank 2 из бэкапа **той же клавиатуры**:

```bash
dfu-util -a 0 -s 0x08010000 -D hhkb-bank2-stock-firmware_64k.bin
```

Для полного восстановления бэкапа той же платы отдельно запишите Flash и EEPROM. Option Bytes восстанавливайте только при необходимости и только из этого же бэкапа.

```bash
dfu-util -a 0 -s 0x08000000 -D hhkb-full-flash_128k.bin
dfu-util -a 2 -s 0x08080000 -D hhkb-eeprom_6k.bin
# Только при необходимости и из бэкапа этой же платы:
dfu-util -a 1 -s 0x1FF80000 -D hhkb-option-bytes.bin
```

DMK можно записать непосредственно во второй банк:

```bash
dfu-util -a 0 -s 0x08010000 -D build/hhkb/dmk_hhkb_stm32l072.bin
```

ROM DFU не гарантирует обновление служебных метаданных PFU Bank 1 или флагов EEPROM. После сброса Bank 1 может отклонить образ. Для обычной установки используйте PFU-обновитель. Повторное чтение подтверждает содержимое Flash, но не принятие образа Bank 1:

```bash
dfu-util -a 0 -s 0x08010000:65536 -U bank2-readback.bin
cmp -n "$(wc -c < build/hhkb/dmk_hhkb_stm32l072.bin)" \
  build/hhkb/dmk_hhkb_stm32l072.bin bank2-readback.bin
```

## Полный бэкап через SWD / J-Link

Подключение SWD на плате HHKB Classic — пять площадок рядом с разъёмом CN3 в два ряда:

```text
GND  NRST  VCC
 SWCLK SWDIO
```

#### Распиновка подключения J-Link к пяти SWD-падам рядом с CN3

| Площадка | Сигнал STM32L072        | Сигнал J-Link        |
| -------- | ----------------------- | -------------------- |
| GND      | Земля                   | GND                  |
| NRST     | NRST                    | RESET (необязателен) |
| VCC      | 3,3 В / опорное питание | VTref                |
| SWCLK    | PA14                    | SWCLK                |
| SWDIO    | PA13                    | SWDIO                |

> [!TIP]
> Клавиатуру можно питать от USB. В таком случае подключите её VCC к VTref J-Link только для измерения опорного напряжения 3,3 В. Либо подайте 3,3 В напрямую от программатора. Не используйте оба источника питания одновременно.

### Скрипт автоматического полного бэкапа

Создайте файл `backup_jlink.jlink`:

```text
r
halt
// 1. Полный дамп Flash: 128 КБ = Bank 1 + Bank 2
savebin hhkb_full_flash_128k.bin 0x08000000 0x00020000

// 2. Заводской Bank 1: 64 КБ
savebin hhkb_bank1_bootloader_64k.bin 0x08000000 0x00010000

// 3. Заводской Bank 2: 64 КБ
savebin hhkb_bank2_stock_firmware_64k.bin 0x08010000 0x00010000

// 4. Встроенный EEPROM: 6 КБ, калибровки EC, серийный номер и флаги
savebin hhkb_eeprom_6k.bin 0x08080000 0x00001800

// 5. Option Bytes STM32L072: защита и параметры загрузки
savebin hhkb_option_bytes.bin 0x1FF80000 0x00000020

q
```

Запустите бэкап одной командой:

```bash
JLinkExe -device STM32L072RB -if SWD -speed 4000 -autoconnect 1 -CommanderScript backup_jlink.jlink
```

### Восстановление через J-Link

Для возврата Flash и EEPROM этой же клавиатуры создайте `restore_jlink.jlink`:

```text
r
halt
loadbin hhkb_full_flash_128k.bin 0x08000000
loadbin hhkb_eeprom_6k.bin 0x08080000
r
g
q
```

Этот сценарий восстанавливает Flash и EEPROM из полного бэкапа. Option Bytes он намеренно не перезаписывает: восстанавливайте их только при подтверждённой необходимости и из бэкапа той же платы.

## Карта памяти

| Область | Адрес                   | Назначение                                                   |
| ------- | ----------------------- | ------------------------------------------------------------ |
| Bank 1  | `0x08000000–0x0800FFFF` | Заводской PFU-обновитель; B4.16 в сохранённом бэкапе Classic |
| Bank 2  | `0x08010000–0x0801FFFF` | Заводская A4.29 или DMK                                      |
| EEPROM  | `0x08080000–0x080817FF` | Заводские данные и настройки DMK                             |

## Восстановление

Для обычного восстановления войдите в Bank 1 через SW6 и установите подходящий заводской `.hfb` через [официальный центр загрузки HHKB (Keymap Tool и обновления прошивки)](https://happyhackingkb.com/download/) или `hhkb_flasher.py`. Запущенный DMK штатная утилита не распознаёт.

DFU или SWD позволяют восстановить сохранённый Bank 2. Полное восстановление Flash, EEPROM или Option Bytes — операция для опытных пользователей: используйте бэкап только той же клавиатуры и не перезаписывайте оригинальные файлы.

## Recovery SW6

Возврат по SW6 включён по умолчанию для Classic и Hybrid, включая ANSI и JIS, и проверен на реальном оборудовании. После входа в Bank 1 верните SW6 в OFF.

При `HHKB_SW6_REBOOT_TO_BANK1=1` запуск DMK с SW6 в ON инвалидирует Bank 2, стирает его первую 128-байтную страницу векторов и перезагружает MCU в Bank 1. В стёртой странице находятся начальный указатель стека и вектор сброса, поэтому Bank 1 больше не может передать выполнение в Bank 2. Это сохраняется после отключения питания: Bank 2 не загрузится, пока в него заново не будет записан полный совместимый образ через PFU-обновитель, DFU или SWD.

После этого перехода через Bank 1 можно установить последнюю подходящую заводскую прошивку со [страницы загрузок HHKB](https://happyhackingkb.com/download/) — штатным Keymap Tool либо `hhkb_flasher.py`. Выберите HFB для обычной Classic или Classic Type-S. В обычной работе SW6 должен быть OFF.

### SW5 + SW6: очистка настроек DMK и переход в Bank 1 (dev)

Комбинация реализована в ветке **dev**. Для обычного обновления с сохранением настроек DMK используйте **SW5 OFF + SW6 ON**. При **SW5 ON + SW6 ON** запуск сначала очищает распознанные записи DMK в EEPROM, затем выполняет обычный возврат в Bank 1. Оба переключателя должны оставаться ON в течение интервала антидребезга; один SW5 ничего не стирает.

При запуске:

| SW5 | SW6 | Действие восстановления / очистки |
| --- | --- | --- |
| OFF | OFF | Обычный запуск DMK; без очистки EEPROM и перехода в Bank 1 |
| ON | OFF | Обычный запуск DMK; без очистки EEPROM и перехода в Bank 1 |
| OFF | ON | Переход в Bank 1 с сохранением настроек DMK |
| ON | ON | Очистка распознанных записей DMK, затем переход в Bank 1 |

При SW6 OFF у SW5 остаётся обычная функция DIP-переключателя; сам по себе он не запускает восстановление или очистку.

1. Отключите USB; у Hybrid также извлеките батарейки, чтобы произошёл полный запуск MCU.
2. Включите SW5 и SW6, затем подключите USB.
3. Не отключайте питание до появления USB-устройства PFU Bank 1. После этого верните SW6 в OFF, а SW5 — в обычное положение перед прошивкой.

Удаляются принадлежащие DMK сжатые слоты и заголовок владения, а также распознанные старые записи DMK1/DMK2 с раскладкой и записи настроек/калибровки DMK. Форматы ANSI и JIS распознаются независимо от запущенной сборки. Старые снимки и версионированная калибровка проверяются по контрольным суммам; неизвестные записи и записи с неверной контрольной суммой остаются нетронутыми. Это **не** стирание всех 6 КиБ EEPROM и не сброс раскладок PFU. Заводские таблицы сенсоров, журнал подключений Bluetooth PFU, метаданные модели/версии и прошивка Nordic сохраняются. Обычный путь SW6 по-прежнему меняет свои поля статуса/CRC Bank 2 и стирает страницу векторов Bank 2.

При ошибке записи EEPROM Bank 2 не инвалидируется и не стирается: запуск останавливается, а `hhkb_recovery_flash_error` получает `0x40000000` для проверки через SWD. Подключите стабильное питание и повторите SW5+SW6. Не отключайте питание во время очистки. Новая комбинация проверяется хостовыми тестами и сборками; проверка на железе ещё нужна.

### Отличия EEPROM Classic и Hybrid

Доступный полный бэкап EEPROM (`hhkb-eeprom.bin`, 6144 байта; в парном Flash идентификатор **PD-KB401W**) относится к Classic. Отдельного полного дампа EEPROM Hybrid не найдено, поэтому столбец Hybrid ниже основан на разборе стока A0.48 в [l3tnun/hhkb_hybrid](https://github.com/l3tnun/hhkb_hybrid), а не на побайтовом сравнении двух бэкапов.

| Область | Доступный бэкап Classic | Карта EEPROM Hybrid A0.48 |
| --- | --- | --- |
| `0x08080380–0x0808047F` | Все байты нулевые | Журнал подключений Bluetooth: 16 × 16 байт |
| `0x08080700–0x08080CFF` | Все байты нулевые | Штатная таблица раскладки B, 1536 байт |
| `0x08081400–0x080816FF` | Все байты нулевые | Вторая часть штатной таблицы раскладки A, 768 байт |
| `0x08081000–0x080812FF` | Индивидуальные ненулевые таблицы сенсоров | Индивидуальные таблицы сенсоров/калибровки; сохраняются данные именно своей платы |
| Поля восстановления | В бэкапе `0x348=0`, `0x360=1`, байты CRC по `0x370=07 DE`; DMK Classic при восстановлении меняет `0x348` и CRC | DMK Hybrid при восстановлении обнуляет байт разрешения Bank 2 по `0x360` |

Формат сжатой записи **DMK** одинаков для Classic и Hybrid с одинаковой геометрией матрицы. Настройки питания, кнопки и LED Hybrid упакованы в зарезервированные поля и не требуют отдельной области EEPROM. ANSI и JIS имеют разные идентификаторы владения и геометрию калибровки. Нулевая область Classic не означает свободное место в Hybrid; переносить EEPROM-бэкап Classic на Hybrid нельзя.

## Способы прошивки DMK и ограничения

На текущий момент существуют три способа прошить клавиатуру на DMK:

1. **Аппаратный программатор / отладчик (SWD):** подключение через контакты CN3 (STM32) с прямой записью Bank 2 по адресу `0x08010000`. Требует вскрытия корпуса и пайки/подключения программатора.
2. **Активация встроенного ROM DFU:** замыкание правых площадок R6 и R85 при подключении USB (поднятие `BOOT0`). Также требует разборки клавиатуры и замыкания контактов на плате.
3. **Штатный PFU-обновитель или `hhkb_flasher.py` с пропатченным официальным `.hfb`:** подмена секции STM32 (Bank 2) с сохранением оригинальной nRF-секции (для Hybrid).

Все эти методы имеют ограничения и существенно сужают аудиторию пользователей (требуют разборки или наличия оригинального проприетарного файла прошивки от производителя).

### Механизм валидации обновления nRF и поведение Bank 1 (Hybrid)

Эксперименты на реальном оборудовании показали следующее:

- Если собрать «чистую» прошивку DMK со сгенерированной пустой или тестовой секцией Bluetooth nRF (например, через `patch_hybrid_hfb.py --make-stm32-only`):
  1. Bootloader модуля Nordic nRF52832 проверяет промежуточную область (staging area с 7 словами заголовка, CRC16 и MD5).
  2. Обнаружив несовпадение контрольной суммы или MD5, nRF отклоняет обновление, очищает промежуточную область и **безопасно сохраняет свою текущую заводскую прошивку**.
  3. Однако после того, как Nordic отклоняет прошивку, **STM32 Bank 1 также отклоняет обновление** и отказывается передавать управление в Bank 2 (не выставляет флаг успешной загрузки `0x08080360 = 1`). В результате чистая прошивка из CI не может запуститься штатным образом.

В теории можно было бы сгенерировать чистый валидный образ для nRF (с верными заголовками и MD5), который загрузчик nRF примет. Это позволило бы получить полностью работающую USB-клавиатуру, но модуль Bluetooth перестал бы функционировать (до отката на официальную прошивку PFU). Возможный многостадийный сценарий обхода описан в [руководстве по установке](install.md#теоретический-многостадийный-сценарий-обхода-multi-stage-workaround).

## Бэкап и восстановление STM32L072RBT6 (Classic и Hybrid)

Основной микроконтроллер клавиатур HHKB Classic и Hybrid — **STMicroelectronics STM32L072RBT6** (ARM Cortex-M0+, LQFP64, 128 КБ Flash, 20 КБ SRAM, 6 КБ встроенного EEPROM).

### Разметка памяти STM32: различия Classic и Hybrid

Оба семейства используют двухбанковую организацию Flash, однако логика проверки и адреса флагов в EEPROM различаются:

| Область                         | Диапазон адресов                   | Назначение (Classic)                                  | Назначение (Hybrid)                                                                     |
| :------------------------------ | :--------------------------------- | :---------------------------------------------------- | :-------------------------------------------------------------------------------------- |
| **Bank 1**                      | `0x08000000–0x0800FFFF` (64 КБ)    | Заводской загрузчик-обновитель PFU                    | Заводской загрузчик-обновитель PFU (управляет и STM32, и nRF через SPI)                 |
| **Bank 2**                      | `0x08010000–0x0801FFFF` (64 КБ)    | Рабочая прошивка (заводская A4.xx / A8.xx или DMK)    | Рабочая прошивка (заводская A0.xx / A2.xx или DMK)                                      |
| **Bank 3 / Reserved**           | `0x08020000–0x0802FFFF` (64 КБ)    | Не используется в текущей схеме PFU                   | Не используется в текущей схеме PFU                                                     |
| **Встроенный EEPROM**           | `0x08080000–0x080817FF` (6 КБ)     | Заводские калибровки, флаги Bank 2                    | Заводские калибровки, флаги Bank 2 и Bluetooth                                          |
| ↳ _Флаги статуса Bank 2_        | `0x08080348` и `0x08080370`        | Статус (`0x01` = повреждён) и 2 байта CRC тега Bank 2 | В Hybrid для разрешения старта Bank 2 используется байт `0x08080360` (`0x01` = валиден) |
| ↳ _Калибровки матрицы_          | `0x08081000–0x080812FF`            | Заводские базовые линии и пороги EC                   | Заводские пороги (структура отличается)                                                 |
| ↳ _Пользовательские данные DMK_ | Несколько участков, 1772 байта | [Сжатые снимки](via-debug.md#сжатое-хранение-eeprom): калибровка, раскладки, макросы, комбо, настройки | Тот же формат плюс настройки питания/кнопки/индикации Hybrid; данные сопряжения PFU остаются отдельно |
| **Option Bytes**                | `0x1FF80000–0x1FF8001F` (32 байта) | Защита от чтения (RDP Level 0/1) и загрузка           | Защита от чтения (RDP Level 0/1) и загрузка                                             |

### Подключение SWD к STM32 (Площадки CN3)

Интерфейс отладки STM32 выведен на пять контактных площадок рядом с разъёмом CN3 в два ряда:

```text
GND   NRST  VCC
 SWCLK SWDIO
```

- **SWDIO:** вывод PA13 микроконтроллера STM32L072
- **SWCLK:** вывод PA14 микроконтроллера STM32L072
- **NRST:** вывод аппаратного сброса STM32
- **VCC:** 3.3 В (питание платы или опорный сигнал VTref программатора)
- **GND:** земля (0 В)

> [!TIP]
> Клавиатуру можно питать от USB. В таком случае подключите VCC к выводу VTref программатора (например, J-Link) только для согласования уровней 3,3 В. Не подавайте питание от программатора одновременно с подключённым USB-кабелем.

### Бэкап STM32 через J-Link

Создайте файл `backup_stm32.jlink`:

```text
r
halt
// 1. Полный дамп Flash: 128 КБ = Bank 1 + Bank 2
savebin stm32_full_flash_128k.bin 0x08000000 0x00020000
// 2. Заводской Bank 1 (бутлодер PFU): 64 КБ
savebin stm32_bank1_bootloader_64k.bin 0x08000000 0x00010000
// 3. Текущий Bank 2: 64 КБ
savebin stm32_bank2_app_64k.bin 0x08010000 0x00010000
// 4. Встроенный EEPROM: 6 КБ (калибровки, серийник, флаги загрузки)
savebin stm32_eeprom_6k.bin 0x08080000 0x00001800
// 5. Option Bytes: 32 байта
savebin stm32_option_bytes.bin 0x1FF80000 0x00000020
q
```

Запуск дампа:

```bash
JLinkExe -device STM32L072RB -if SWD -speed 4000 -autoconnect 1 -CommanderScript backup_stm32.jlink
```

### Восстановление STM32 через J-Link

Для восстановления создайте `restore_stm32.jlink`:

```text
r
halt
loadbin stm32_full_flash_128k.bin 0x08000000
loadbin stm32_eeprom_6k.bin 0x08080000
r
g
q
```

Запуск восстановления:

```bash
JLinkExe -device STM32L072RB -if SWD -speed 4000 -autoconnect 1 -CommanderScript restore_stm32.jlink
```

## Бэкап и восстановление Nordic nRF52832 (Только Hybrid)

В HHKB Hybrid радиоподсистема Bluetooth реализована на отдельном модуле **Taiyo Yuden EYSHCNZWZ**, сердцем которого является однокристальный чип **Nordic Semiconductor nRF52832** ([Datasheet модуля](https://docs.rs-online.com/2d1f/0900766b81699ea1.pdf)) (ARM Cortex-M4F @ 64 МГц, 512 КБ Flash, 64 КБ RAM).

### Разметка памяти Nordic nRF52832

Flash-память чипа nRF52832 (512 КБ) организована под стек Nordic SoftDevice S132 и кастомный загрузчик PFU:

| Область                             | Диапазон адресов                 | Назначение                                                                         |
| :---------------------------------- | :------------------------------- | :--------------------------------------------------------------------------------- |
| **MBR**                             | `0x00000000–0x00000FFF` (4 КБ)   | Master Boot Record Nordic                                                          |
| **SoftDevice S132**                 | `0x00001000–0x00025FFF` (148 КБ) | BLE-стек SoftDevice v6.0.0                                                         |
| **Приложение (App)**                | `0x00026000–0x00031FFF` (48 КБ)  | Заводская прошивка Bluetooth HHKB Hybrid                                           |
| **Промежуточная область (Staging)** | `0x00036000–...`                 | Буфер приёма обновлений по SPI от STM32 (заголовок в `0x36000`, образ с `0x37000`) |
| **FDS (Flash Data Storage)**        | `0x00075000–0x00077FFF` (12 КБ)  | Данные сопряжений (хранилище Nordic FDS, метка `0xDEADC0DE`)                       |
| **Загрузчик (Bootloader)**          | `0x00078000–0x0007FFFF` (32 КБ)  | Заводской бутлодер обновления `FwUpdate_*` (`UICR.BOOTLOADERADDR = 0x78000`)       |
| **UICR**                            | `0x10001000–0x100013FF` (1 КБ)   | User Information Configuration Registers (адрес бутлодера, настройки защиты)       |

### Подключение SWD к Nordic nRF52832 (Разъём CN6 и выводы модуля)

На плате Hybrid для отладки и заводского программирования чипа Nordic предусмотрен отдельный интерфейс:

- **Разъём / площадки CN6:** заводской интерфейс **SWD для микросхемы Nordic nRF52832**.
- **Альтернативно (напрямую на контакты модуля Taiyo Yuden EYSHCNZWZ):**
  - **Pin 14:** `SWDIO`
  - **Pin 15:** `SWDCLK` (вывод **15** маркирован шелкографией на плате рядом с модулем)
  - **Pin 20:** `RESET` (nRF52 P0.21 / nRESET)
  - **VDD:** Pin 11/12 (1.7–3.6 В)
  - **GND:** Pin 42–45, 47, 48

### Бэкап nRF52832 через J-Link / nrfjprog

Перед чтением убедитесь, что в UICR не активирована защита от чтения памяти (APPROTECT).

Создайте командный файл `backup_nrf52.jlink`:

```text
r
halt
// 1. Полный дамп Flash: 512 КБ (MBR + SoftDevice + App + FDS + Bootloader)
savebin nrf52_full_flash_512k.bin 0x00000000 0x00080000
// 2. UICR: 1 КБ конфигурационных регистров
savebin nrf52_uicr_1k.bin 0x10001000 0x00000400
q
```

Запуск дампа:

```bash
JLinkExe -device nRF52832_xxAA -if SWD -speed 4000 -autoconnect 1 -CommanderScript backup_nrf52.jlink
```

Либо с помощью официальной утилиты `nrfjprog`:

```bash
nrfjprog --family NRF52 --readcode nrf52_full_flash_512k.hex
nrfjprog --family NRF52 --readuicr nrf52_uicr.hex
```

### Восстановление nRF52832

Для восстановления фабричного состояния модуля Bluetooth:

```text
r
halt
loadbin nrf52_full_flash_512k.bin 0x00000000
loadbin nrf52_uicr_1k.bin 0x10001000
r
g
q
```

Запуск восстановления:

```bash
JLinkExe -device nRF52832_xxAA -if SWD -speed 4000 -autoconnect 1 -CommanderScript restore_nrf52.jlink
```

Или через `nrfjprog`:

```bash
nrfjprog --family NRF52 --program nrf52_full_flash_512k.hex --chiperase --reset
```

### Межчиповое соединение по SPI (STM32 ↔ Nordic nRF52832)

В архитектуре HHKB Hybrid микроконтроллер **Nordic является ведущим (SPI Master)**, а **STM32 — ведомым (SPI Slave)**:

- **Конфигурация SPI:**
  - **STM32:** периферийный блок `SPI1` в режиме Slave
  - **Nordic:** блок `SPI0` в режиме Master
  - **Режим SPI:** Mode 3 (`CPOL = 1`, `CPHA = 1`)
  - **Формат:** 8-битный, MSB first
  - **Тактовая частота шины (Nordic SPI clock):** 125 кГц

- **Соединение выводов шины SPI (сопоставление с [даташитом EYSHCNZWZ](https://docs.rs-online.com/2d1f/0900766b81699ea1.pdf)):**
  - **SCK:** STM32 `PB3` ↔ Nordic `P0.25` (**Pin 27** модуля)
  - **MISO:** STM32 `PB4` ↔ Nordic `P0.24` (**Pin 26** модуля)
  - **MOSI:** STM32 `PB5` ↔ Nordic `P0.23` (**Pin 25** модуля)
  - **CS / NSS:** STM32 `PA15` ↔ Nordic `P0.22` (**Pin 24** модуля)

- **Сигналы управления и прерываний:**
  - **STM32 `PB6` → Nordic `P0.18`:** Линия запроса / пробуждения (Attention / Request). Когда STM32 хочет передать пакет клавиш или статус батареи, он выдает короткий низкий импульс (`LOW`), заставляя Nordic инициировать SPI-транзакцию.
  - **STM32 `PD2`:** Линия управления питанием/разрешением Nordic (Enable). Низкий уровень (`LOW`) разрешает работу радиомодуля при нормальной активности.

> [!TIP]
> При наличии логического анализатора (или микроконтроллера RP2040 с анализатором логики) захват трафика этих линий (SCK, MISO, MOSI, CS, Attention PB6) крайне полезен для анализа обмена пакетами, особенно в моменты старта устройства и во время выполнения процедуры обновления прошивки.
