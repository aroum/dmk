# Конфигурация

## Определения сборки

- `HHKB_CLASSIC` собирает прошивку для проводной модели HHKB Classic (ANSI).
- `HHKB_CLASSIC_TYPE_S` собирает прошивку для проводной модели Classic Type-S (ANSI или JIS в связке с `HHKB_JIS`).
- `HHKB_HYBRID` собирает прошивку для беспроводных моделей Hybrid и Hybrid Type-S (включает SPI-обмен со штатным nRF, управление батареей, профилями и режим STOP).
- `HHKB_JIS` активирует поддержку 69-клавишной японской матрицы JIS (разреженная матрица, 15 колонок, клавиши Kana/Henkan/Muhenkan и стрелочный блок).
- `HHKB_SCAN_DIAGNOSTICS` добавляет счётчики для измерений через SWD.

## Сканирование матрицы

- **ANSI (60 клавиш):** матрица 15 столбцов × 4 строки (все позиции заселены).
- **JIS (69 клавиш):** матрица 15 столбцов × 5 логических строк (69 физических переключателей, активная маска `populated`).

DMK выбирает столбец мультиплексора, импульсом `PC8` разряжает накопительный конденсатор `C57`, переводит опрашиваемую строку в активный `LOW`, выдерживает стабилизацию аналогового сигнала, выполняет измерение АЦП (с усреднением или без), возвращает строку в `HIGH` и переходит к следующей клавише. Линия `PC14` питает аналоговую часть матрицы, `PC7` активирует измерительный операционный усилитель, `PA1` служит входом `ADC1_IN1`.

Таймерный сканер матрицы включён по умолчанию. [VIA](https://www.usevia.app/) позволяет выбрать целевую частоту сканирования: 50, 125, 250, 500 или 1000 Гц (при 1000 Гц целевой период опроса составляет 950 мкс). Сканер исполняется непосредственно из быстрой памяти SRAM, а аппаратный таймер TIM2 обеспечивает прецизионные аналоговые задержки.

## Распиновка матрицы и периферии

- **Матрица:** 4 строки × 15 столбцов (ANSI) либо до 5 строк × 15 столбцов (JIS).
- **Строки:** `PB0`, `PB1`, `PB2`, `PB10` (маски `GPIOB` — `0x001`, `0x002`, `0x004`, `0x400`).
- **Столбцы:** два аналоговых мультиплексора 74HC4051. `PC6` выбирает U1 (столбцы 0–7), `PB15` — U2 (столбцы 8–14); выводы `PB12`, `PB13`, `PB14` задают адрес канала.
- **Аналоговый тракт:** `PC14` — питание сенсоров, `PC7` — разрешение ОУ, `PC8` — аппаратный сброс емкости C57, `PA1` — аналоговый вход АЦП (`ADC_IN1`).
- **DIP-переключатели:** `PA3`–`PA7` и `PC4`, активный низкий уровень.
- **Светодиоды (LED):** `PA8` и `PA9` (Classic и Hybrid). [VIA](https://www.usevia.app/) независимо назначает Off, Debug heartbeat, Caps Lock, Fn layer или System 2; по умолчанию PA8 показывает Caps Lock, PA9 — Fn layer.

## Заводские данные и калибровка

Заводские пороги классического режима загружаются из EEPROM самой клавиатуры при старте. Поэтому один образ DMK сохраняет индивидуальные пороги при установке на другую плату. Пользовательская калибровка хранит base и peak для каждой клавиши в отдельной записи EEPROM (`0x08081500`). Отключение пользовательской калибровки выбирает диапазон по умолчанию и не перезаписывает заводские таблицы.

## DIP-переключатели

SW1–SW5 читаются, но пока не имеют фиксированных действий DMK. SW6 по умолчанию запускает возврат в Bank 1. Для выбора пары базового/Fn-слоя назначьте в VIA коды System 1 и System 2. Fn + Tab по-прежнему включает Caps Lock.

## Только Hybrid: транспорт, профили и питание

PC13 имеет низкий уровень при питании от USB и высокий при питании от батарей. На батареях DMK передаёт шестиклавишные HID-отчёты штатному nRF по SPI и использует отдельную частоту опроса матрицы. При USB-подключении отчёты по умолчанию идут по USB, а частота берётся из обычного меню VIA. **BT / USB** позволяет выбрать последний Bluetooth-профиль даже при подключённом USB. Если кабеля нет, выбор USB вступит в силу после его подключения. Медиа-клавиши через Bluetooth пока не реализованы. Таймингами отчётов Bluetooth управляет Nordic независимо от сканирования матрицы.

Есть четыре Bluetooth-профиля. **BT Select 1–4** выбирает существующую привязку; **BT Pair 1–4** запускает сопряжение в выбранном слоте и может заменить прежнюю привязку. **BT Next** переключает слоты по кругу. Последний выбранный слот сохраняется в EEPROM и запрашивается при запуске от батарей. **BT Pair Last** сопрягает этот слот.

Штатный nRF — ведущий SPI на PA15/PB3–PB5 (режим 3, 125 кГц). PB6 запрашивает опрос, PD2 управляет радиомодулем. Приложение STM32 находится в Bank 2 с адреса `0x08010000`; образ nRF упаковщик сохраняет.

Общие [настройки VIA](via-debug.md) также управляют частотой сканирования по USB, калибровкой, точкой срабатывания и гистерезисом, Rapid Trigger при соответствующей сборке, оверсемплингом АЦП, таймингами hold-tap и базовыми режимами двух светодиодов. Настройки батареи, профилей и PC5, которых нет у Classic, перечислены ниже. Нельзя считать, что заводская таблица калибровки Classic подходит для Hybrid.

### Режимы питания и PC5

- **USB:** клавиатура обычно передаёт отчёты по USB. Как и в исходной реализации, действие OFF работает только от батарей.
- **Активный режим от батарей:** передача по Bluetooth; частота сканирования по умолчанию 200 Гц. В VIA доступны 50, 125, 200 и 250 Гц.
- **Сон:** включается кейкодом, действием PC5 или по бездействию. Тайм-аут по умолчанию 30 минут; во время сопряжения он ограничен 10 минутами. `0` отключает автоматический сон. Если **Wake with matrix** выключен, сон останавливает nRF и переводит STM32 в STOP. Удержание PC5 одну секунду или подключение USB пробуждает через сброс. Если пробуждение матрицей включено, МК продолжает работать с пониженной активностью и опрашивает матрицу раз в секунду; пробуждают PC5, клавиша или USB. Такой режим потребляет больше, чем STOP.
- **OFF:** на батареях удержание PC5 две секунды (по умолчанию) или **BT Power** выключает nRF, АЦП, питание датчиков и таймер матрицы, затем включает STOP. Удержание PC5 одну секунду либо подключение USB перезапускает плату. LPTIM1 пробуждает МК примерно раз в 1,7 секунды для обслуживания активного независимого watchdog. Измеренный ток и известная проблема пробуждения описаны ниже.

Короткое нажатие PC5 длится 0–0,5 секунды и по умолчанию показывает номер подключённого профиля. В VIA можно выбрать отсутствие действия, показ заряда, сон, следующий профиль или переключение между последним профилем и USB. Длинное нажатие срабатывает через две секунды и по умолчанию выключает клавиатуру; другие варианты — сон и сопряжение последнего профиля. Пробуждение из OFF удержанием PC5 одну секунду не переназначается.

Заводской пример тоже использует аппаратный STOP для OFF и сна с пробуждением от PC5 или USB и последующим сбросом. [Код STOP в DMK](../../modules/hybrid/hybrid_stop.c) адаптирует только этот фрагмент под лицензией MIT. Режим с пробуждением матрицей 1 Гц оставляет МК работающим.

### Железо и лицензия

Распиновка ANSI-матрицы и SPI-протокол опираются на приложенное исследование `hhkb_hybrid`. Его файлы `nrf_spi.c` и `power.c` имеют заголовки MIT; заимствованы только обработка протокола и последовательность пробуждения из STOP. Атрибуция и полный текст лицензии находятся в [LICENSE.protocol](../../modules/hybrid/LICENSE.protocol). Заводской и модифицированный PFU-контейнеры не включаются в Git.

Координаты JIS и карта заводской калибровки Hybrid пока не подтверждены. Успешная сборка не доказывает запуск, сопряжение, пробуждение из STOP и расход батарей на реальной плате.


### Измеренное потребление и пороги батареи (только Hybrid)

Пользовательские измерения, полученные 20 ноября 2026 года, выполнены по Bluetooth при питании 3,0 В. Они относятся к проверенному экземпляру Hybrid и прошивке, а не гарантируют такие же значения на каждой плате. Ниже ток указан в мА; пики отмечены отдельно.

| Режим | DMK, 1000 Гц | DMK, 50 Гц | DMK, 50 Гц + оверсемплинг 4x | Сток |
| --- | --- | --- | --- | --- |
| Запуск | 12,5–14 | 12,5–15 | 13 | 3,3 |
| Покой | 10,33–10,7 | 10,5–12 | 10,9–11,7 | 3,28 |
| Набор | 11–13; однократный пик 14 | 13 | 13–13,5; пики 15 | 3,53–3,58 |
| OFF | 4–4,5 | 4 | 4,2 | 0,21 |
| Сон | 4 | 4 | 4 | Не наблюдался |
| Сон с пробуждением матрицей | 7,4 | 7,5 | 7,3 | Не измерено |

Сейчас DMK потребляет от батарей значительно больше стока: в OFF примерно в 19–21 раз. Одно снижение частоты матрицы в этих измерениях не уменьшило ток покоя. Энергосбережение OFF/сна пока не подтверждено: тестер также воспроизвёл отказ пробуждения через PC5, после которого требуется извлечение батарей. Описанный выше порядок пробуждения — предполагаемое поведение. Захват SWD перед STOP подтвердил работу входа PC5, маршрутизацию EXTI и счёт LPTIM, но после продолжения в STOP доступ отладчика пропал; достоверного снимка после STOP нет.

Обновлённый путь OFF явно выключает USB-трансивер и HSI48, останавливает TIM2, сбрасывает выходы строк и мультиплексоров и ждёт отпускания кнопки OFF перед входом в STOP. Изменения собраны, но ещё не измерены на плате; приведённые выше значения относятся к прежним измерениям. Для диагностики через SWD переменная `hhkb_stop_stage` отмечает: 1 — подготовка, 2 — ожидание отпускания кнопки, 3 — перед WFI, 4 — возврат из WFI, 5 — отсчёт удержания кнопки, 6 — запрос сброса. `hhkb_stop_wake_count` считает возвраты из WFI. Обе переменные находятся в RAM и обнуляются при сбросе.

На батареях задача USB теперь отсоединяет и деинициализирует TinyUSB, выключает USB-трансивер, CRS и HSI48; питание проверяется раз в 100 мс, после подключения кабеля USB инициализируется повторно. При питании от батарей CPU/AHB всегда работает на 16 МГц, от USB — на 32 МГц, включая передачу по Bluetooth при питании USB. Для матрицы на батареях доступны 50, 125, 200 (по умолчанию) и 250 Гц. Ранее сохранённые 500/1000 Гц загружаются как 200 Гц. На батареях CPU теперь работает напрямую от HSI16; PLL и MSI выключены. Делитель TIM2 перенастраивается для сохранения счётчика 4 МГц, SysTick — для сохранения тика RTOS, делитель АЦП — для сохранения частоты АЦП 16 МГц. Во сне с пробуждением матрицей оба LED погашены. Нужна аппаратная проверка: ток, период матрицы, удержание клавиш, подключение/отключение USB и циклы OFF/пробуждения. Новых подтверждённых значений потребления пока нет.

Дополнительные изменения выключают неиспользуемые буферы опоры HSI48/VREFINT/датчика температуры, регулятор АЦП в окончательном OFF и TIM2 между проверками пробуждения матрицей раз в секунду. Запросы к неотвечающему Nordic после пяти попыток замедляются с 5 до 100 мс; принятые данные SPI или новый отчёт клавиш возвращают быстрые повторы. CPU на батареях остаётся на согласованных 16 МГц; режим 4 МГц из примера пока не перенесён. Tickless idle RTOS пока выключен.

Терминальный путь STOP также очищает ожидающие исключения SysTick/PendSV, на которые не действуют регистры очистки внешних IRQ NVIC, и оставляет в EXTI только PC5, PC13 и LPTIM. Это убирает возможные лишние источники пробуждения, но ещё не доказывает причину ранее наблюдавшегося отказа включения.

**Проверка потребления:** тот же Hybrid, питание 3,0 В, Bluetooth-соединение с тем же хостом, USB отключён, диагностические каналы и декоративные/heartbeat LED выключены. Перед замером закройте OpenOCD и перезапустите питание: настройки отладки низкого энергопотребления меняют ток STOP. Запишите ток запуска, покоя, набора, OFF и сна с пробуждением матрицей и без него; повторите для 50 и 200 Гц, с оверсемплингом и без. Ориентиры из стокового замера: 3,28 мА в покое, 3,53–3,58 мА при наборе, 0,21 мА в OFF; это цели, а не достигнутые значения DMK. Проверьте десять циклов OFF/пробуждения PC5, подключение/отключение USB, отпускание клавиш, калибровку и диапазоны АЦП после смены тактирования. Если ток покоя остаётся высоким, перед дальнейшим снижением частоты нужно отдельно измерить вклад STM32, Nordic и аналоговой платы.

Индикация батареи использует дискретные аппаратные пороги, а не непрерывный пересчёт напряжения в проценты. При изменении напряжения питания получены следующие результаты:

- **Выше порога низкого заряда (на экране 100%, четыре оранжевых мигания):** наблюдалось от 3,00 до 2,25 В.
- **15%, три мигания:** от 2,24 до 2,14 В.
- **5%, два мигания:** от 2,13 до 2,03 В.
- **0%, одно мигание:** при 2,02 В; это не означает немедленного отключения.
- При 1,71 В клавиатура уже не работала. Точное напряжение отключения не определено.

Переходы порогов наблюдались между 2,25–2,24 В, 2,14–2,13 В и 2,03–2,02 В. Это измерения одного экземпляра; допуски и гистерезис не исследованы. Показание 100% означает отсутствие активных порогов низкого заряда, а не полный заряд батареи. Подключение USB не заряжает батареи.

## Частота сканирования и передачи Bluetooth (Hybrid)

Частота сканирования матрицы задаётся отдельно от передачи отчётов Nordic. Таймингами Bluetooth управляет отдельный радиочип. Тестер сообщил о согласованном BLE-интервале 15 мс (около 66,67 интервала соединения/с) на своём хосте. Это не универсальный предел Bluetooth 50 Гц и не гарантия одного HID-отчёта на интервал. Скрипт HID показал 21,9 отчёта/с при наборе, включая паузы и задержки ОС; он не измеряет интервал соединения. Для подтверждения параметров соединения и их изменений нужна HCI-трасса. Штатная матрица сканируется примерно с частотой 50 Гц. Увеличение частоты матрицы само по себе не ускоряет передачу радио.

## Интервалы Bluetooth HID на macOS (Hybrid)

Отключите USB-кабель HHKB, подключите клавиатуру по Bluetooth и запустите из корня репозитория:

```bash
uv run --with hidapi python3 tools/hhkb/measure_bt_hid.py --list
uv run --with hidapi python3 tools/hhkb/measure_bt_hid.py --device 0 --seconds 20
```

Замените 0 на индекс HHKB из списка. Если у терминала нет доступа к отчётам, разрешите мониторинг ввода в настройках macOS и перезапустите терминал. Во время замера нажимайте и отпускайте несколько клавиш. Скрипт сохраняет только метки времени, выводит min, медиану, p95 и max интервалов. Результат зависит от темпа нажатий и буферизации macOS. Интервал соединения BLE и частоту сканирования матрицы он не измеряет.

### PacketLogger

Войдите в [Apple Developer Downloads](https://developer.apple.com/download/all/) и скачайте **Additional Tools for Xcode**. Откройте DMG, найдите `PacketLogger.app` в папке Hardware и скопируйте в Applications.

```bash
open -a PacketLogger
mdfind 'kMDItemFSName == "PacketLogger.app"'
```

Если захват недоступен, установите профиль Bluetooth для macOS по [инструкции Apple](https://developer.apple.com/bug-reporting/profiles-and-logs/). Начните захват до переподключения Hybrid, затем выполните несколько нажатий. Найдите успешное событие **LE Connection Complete** или **LE Enhanced Connection Complete** и последующие **LE Connection Update Complete** для того же handle. Значение поля в единицах HCI умножается на 1,25 мс. Если PacketLogger уже показывает миллисекунды, используйте их напрямую.

Прошивка DMK для HHKB (Classic и Hybrid, ANSI и JIS) поддерживает вывод диагностических логов в реальном времени через стандартный интерфейс USB HID Console. Это позволяет отслеживать работу емкостной матрицы EC, измерять реальные значения АЦП, контролировать частоту сканирования и анализировать команды конфигуратора.

По умолчанию весь вывод отладки **отключен**, чтобы не нагружать микроконтроллер и USB-шину.
