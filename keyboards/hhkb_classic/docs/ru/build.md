# Сборка

Запускайте сборку из корня репозитория. Используйте стандартную передачу определений DMK.

```bash
# Classic: полная текущая конфигурация
./build_all.sh -b hhkb_classic -d HHKB_RAPID_TRIGGER,HHKB_FACTORY_THRESHOLDS,HHKB_ADC_16MHZ,HHKB_ADC_OVERSAMPLING

# Classic Type-S: та же конфигурация и определение модели
./build_all.sh -b hhkb_classic -d HHKB_TYPE_S,HHKB_RAPID_TRIGGER,HHKB_FACTORY_THRESHOLDS,HHKB_ADC_16MHZ,HHKB_ADC_OVERSAMPLING
```

```powershell
.\build_all.ps1 -Keyboard hhkb_classic -Define HHKB_RAPID_TRIGGER,HHKB_FACTORY_THRESHOLDS,HHKB_ADC_16MHZ,HHKB_ADC_OVERSAMPLING
.\build_all.ps1 -Keyboard hhkb_classic -Define HHKB_TYPE_S,HHKB_RAPID_TRIGGER,HHKB_FACTORY_THRESHOLDS,HHKB_ADC_16MHZ,HHKB_ADC_OVERSAMPLING
```

STM32L072 выбирается через `DEFAULT_MCU` в конфигурации клавиатуры, поэтому в команде сборки не нужен аргумент MCU. `HHKB_TYPE_S` нужен только для Classic Type-S. В каталоге результата создаются контейнер `.hfb` для PFU и сырой `.bin` для Bank 2; сборка не прошивает клавиатуру.

HFB получает версию A4.50 для Classic и A8.50 для Type-S. Упаковщик вычисляет обе контрольные суммы и задаёт соответствующий идентификатор модели PFU.

## Контейнер HFB и варианты моделей

Файл HHKB `.hfb` имеет ровно 65 570 байт:

```text
+---------------------------------------------------------------+
| Внешний CRC-16/MCRF4XX, little-endian (2 байта)                |
+---------------------------------------------------------------+
| Внутренний CRC-16/MCRF4XX полезной нагрузки Bank 2 (2 байта)   |
+---------------------------------------------------------------+
| Прошивка Bank 2, дополненная 0xFF (65 536 байт)                |
+---------------------------------------------------------------+
| Постфикс: 14 × 0xFF, ID модели (6), BCD-версия (4), 6 × 0xFF  |
+---------------------------------------------------------------+
```

Обе контрольные суммы используют отражённый полином `0x8408`, начальное значение `0xFFFF` и не используют финальный XOR. Внутренний CRC зависит от полезной нагрузки, это не постоянный тег модели. Образ линкуется для Bank 2 по адресу `0x08010000`.

Для этого порта Classic и Classic Type-S используют одинаковые STM32L072RB, матрицу 4 × 15, мультиплексоры 4051 и разметку Bank 2 размером 64 КиБ. Видимые прошивке различия — идентификатор PFU и линейка версии:

| Параметр               | Classic     | Classic Type-S |
| ---------------------- | ----------- | -------------- |
| ID модели              | `AHHX01`    | `AHHS01`       |
| Линейка версий         | `A4.xx`     | `A8.xx`        |
| Текущая версия HFB DMK | A4.50       | A8.50          |
| Размер контейнера      | 65 570 байт | 65 570 байт    |

`tools/hhkb/make_hfb.py` собирает оба варианта и автоматически считает CRC. При ручном запуске используйте `--model AHHX01 --version A4.50` либо `--model AHHS01 --version A8.50`.

## 3. Потребление памяти (Flash и RAM)

Bank 2 предоставляет 65 536 байт Flash. Последняя локальная сборка со всеми функциями (`HHKB_RAPID_TRIGGER`, `HHKB_FACTORY_THRESHOLDS`, `HHKB_ADC_16MHZ`, `HHKB_ADC_OVERSAMPLING`) создаёт сырой образ Bank 2 размером 36 116 байт: 55,1% банка; до заполнения остаётся 29 420 байт. `.hfb` размером 65 570 байт содержит дополненный образ Bank 2 и 34 байта метаданных контейнера.

Текущий слинкованный образ STM32L072 резервирует 20 480 байт RAM: `.data` — 288 байт, `.bss` — 16 888 байт, `._user_heap_stack` — 2 048 байт; всего 19 224 байта (93,9%), остаётся 1 256 байт в рамках линковочной разметки. Это распределение при сборке, а не измерение максимальной глубины стека во время работы.

## GitHub Actions

[Workflow Build Firmware](../../../../.github/workflows/build_test.yml) запускается для `push` и `pull_request` в `main`/`master`; его можно запустить вручную через **Actions → Build Firmware → Run workflow**. После успешного запуска скачайте в разделе **Artifacts** нужный архив:

- `hhkb-classic-classic-max-adc-hfb` — обычная Classic, модель `AHHX01`, версия HFB A4.50.
- `hhkb-classic-type-s-max-adc-hfb` — Classic Type-S, модель `AHHS01`, версия HFB A8.50.

В каждом архиве лежат `.hfb` для выбранной модели и [via.json](../../via.json) для загрузки пользовательского меню через VIA Design. Выбирайте архив по модели клавиатуры; сборка Type-S пока проверена компилятором, на плате проверялась обычная Classic.

Обе сборки используют `HHKB_RAPID_TRIGGER,HHKB_FACTORY_THRESHOLDS,HHKB_ADC_16MHZ,HHKB_ADC_OVERSAMPLING`; Type-S дополнительно использует `HHKB_TYPE_S`. VIA v3 и Vial, пользовательская калибровка, настройка частоты, актуации, Rapid Trigger, LED, слоёв и hold-tap включены конфигурацией клавиатуры. `HHKB_ADC_DMA` в workflow не включён.

`HHKB_ADC_OVERSAMPLING` задаёт начальное положение переключателя VIA: ×4 действует при 50–500 Гц, а при 1000 Гц АЦП принудительно использует ×1. Выбор пользователя сохраняется и снова применяется после перехода на 500 Гц или ниже. Публикация артефакта не прошивает клавиатуру; порядок установки описан в [Установке](install.md).
